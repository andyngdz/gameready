Design spec gameready 0.2.0 · Linux

A terminal that explains itself.

Redesign of the gameready CLI: one guided pass that asks everything up front, applies in a single re-probing sweep, and hands back an undo command it means. Every screen below is real output at the width it ships at.

Reflows to real width Re-probes after every apply Nothing asked after the password Warmer, second-person copy
01

Foundations

Marks

One glyph in a two-column gutter. Colour is confirmation, never the only signal.

✔appliedchanged and verified
•already setfound correct, untouched
✘failedwith what was undone
–skippeddeclined, or can't run here
!warningworth reading, not fatal
↻re-checkedthe plan grew mid-run
⠹runninglive region, one at a time

Line anatomy

Name left, evidence right, dot leader between. It reflows, so nothing is authored to 80 columns any more.

✔ Raise vm.max_map_count 65530 → 2147483642
verified, 2 of 2 checks passed
Gutter — mark, 2 cols, always present
Body — plain-language step name, wraps freely
Evidence — the value that proves it, dimmed
Sub-line — the verification, only when it adds something

Palette

Six ANSI slots. Everything else is the terminal's own foreground at three weights.

green
applied · verdict
red
failed only
amber
warnings · size
blue
live · cursor · links
bright
names · headings
dim
evidence · help

❯ gameready explain core.sched.scx-lavd

Switch the CPU scheduler to scx_lavd core.sched.scx-lavd

Why   A frame is a chain of threads waking each other, and the
       kernel's scheduler doesn't know the chain exists — so the
       thread everything is waiting on takes its ordinary turn.
       scx_lavd measures which threads get waited on and runs
       those first.

Gets  Steadier frame times when something else wants the CPU:
       a browser, voice chat, a build. On an idle machine, expect
       nothing. On games that lean on one or two cores it has
       measured slower than the default.

Needs Your password. It changes something outside your home.
Costs ~180 MB downloaded, once.
Here  Would apply. Kernel 6.14.6 supports sched_ext, and no
       sched_ext scheduler is loaded right now.

Would do
  install scx-scheds, scx-tools · 178 MB
  enable and start scx_loader.service
  run scxctl start --sched lavd

Undo     gameready rollback — hands the CPU straight back,
         no reboot.

❯ gameready --help

gameready 0.2.0 — tune a Linux desktop for gaming, and undo it.

Start here
  init       Find your games, ask what you want, apply it.
  rollback   Put everything back. Any run, any time.

Look before you leap
  doctor     What your machine is, and what each tuning would do.
  explain    One tuning: why it exists, and what it'd change here.
  list-games The game profiles I can see, and where each came from.

For scripts and repeat runs
  apply      Apply, optionally one tuning: --step <id>
  selftest   Apply, verify, revert, verify. Proves a tuning works.

Anywhere
  --dry-run  Work out the plan, change nothing.
  --yes      Take every default, install without asking.
  --json     The run report as JSON instead of this.

  Everything gameready changes is reversible, except installing
  a package. It says so before it installs one.

When it goes wrong

Every failure states three things: what broke, what state your machine is in now, and the one command that fixes it.

STEP FAILED, PARTIAL CHANGE UNDONE
✘ CPU scheduler scx_lavd
    scxctl exited 1: no BPF-capable kernel headers.
    The partial change was undone; your CPU is on the
    kernel's own scheduler, exactly as before.
    Everything else in this run applied.
THE UNDO ALSO FAILED
✘ I/O scheduler · sdb
    write failed: read-only sysfs. Undoing it failed too,
    so sdb may still be on bfq.
    gameready rollback --run 2026-08-08T14-22
    will retry it.
SOMETHING ELSE OWNS THE FILE
– Launch options · 2 games
    Steam is open and rewrites this config when it quits,
    so anything I write now is lost.
    Quit Steam, then: gameready apply --pending
A CONFLICT, NOT A FAILURE
– CPU governor
    tuned.service is running and sets the governor on its
    own schedule. Whatever I set, it overrides.
    Your call: systemctl disable --now tuned
    then rerun. I won't disable it behind your back.
COULDN'T TELL — NEVER A REASON TO APPLY
– Proton-GE
    Couldn't check the latest release: github.com timed out.
    I skip rather than guess. Nothing was downloaded.
DRY RUN
Dry run — nothing was touched.
  7 would apply · 1 already set · 1 not applicable
  2 packages would be installed, 6.5 MB

  Drop --dry-run when you're happy with the plan.
